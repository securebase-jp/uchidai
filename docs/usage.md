# 使い方（詳しい手順）

README の「使い方（5 段）」を、画面の操作と環境変数まで含めて書く。すべて手元のサーバで動く。会社カルテはブラウザにだけ保存され、サーバには残らない。

## 起動と環境変数

```bash
pnpm install
cp .env.example .env
pnpm dev     # 画面 http://localhost:5173（Vite）、API http://127.0.0.1:8787（Hono）
```

| 変数                       | 既定                    | 意味                                                                                                          |
| -------------------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_API_KEY`        | （空）                  | Claude API のキー。サーバだけが使い、ブラウザには渡さない。無ければ記事の読解と言い換えが使えない（他は動く） |
| `ANTHROPIC_MODEL`          | `claude-sonnet-5-5`     | 読解・言い換え・依頼文・AI攻撃者に使うモデル                                                                  |
| `SMTP_URL`、`MAIL_FROM`    | （空）                  | 確認依頼をメールで送るとき。無ければ送信箱と `mailto:` リンクだけ                                             |
| `PUBLIC_BASE_URL`          | `http://localhost:5173` | ベンダーの回答リンクの土台。手元のサーバを一時公開するときにその URL を入れる                                 |
| `UCHIDAI_ALLOW_REMOTE_API` | （空）                  | `1` で公開 URL 経由の全 API を許す。会社カルテを扱う API が外から見えるので、デモ以外では設定しない           |
| `WEB_PORT`、`API_PORT`     | `5173`、`8787`          | ポートを変えるとき                                                                                            |

`.env` は読み込まれるだけで、リポジトリには入れない（`.gitignore`、gitleaks）。

### Docker

```bash
docker build -t uchidai .
docker run --rm -p 127.0.0.1:8787:8787 --env-file .env uchidai
```

http://localhost:8787 を開く。`-p 127.0.0.1:8787:8787` で手元だけに公開する。確認依頼の保存先を残すなら `-v uchidai-data:/app/apps/web/.data` を足す。

## 1. 自社のドメインを外から見る（任意、`#/domain`）

国の調査（IPA 事例集の脆弱性事例）で中小企業に実際に見つかった弱点を、公開情報だけで確かめる。

1. ドメイン（例 `example.jp`。国際化ドメイン名は `xn--` の形）を入れ、「トークンを発行する」
2. 表示された TXT レコードを、そのドメインの DNS に追加する。名前は `@`（または空欄）、種別 `TXT`、値 `uchidai-verify=<トークン>`。反映には数分から数時間かかることがある
3. 「所有を確認する」。見つからないときは、いま DNS にある TXT レコードと理由が出る。所有確認は 24 時間で失効する
4. 「外部確認を実行する」。DNS（TXT・MX・A・AAAA・CNAME・PTR）と証明書の公開ログ（crt.sh。1 ドメイン 1 回、応答は 24 時間キャッシュ。0 件のときは保存しない）を参照する。crt.sh が応答しないときは DNS だけで続ける。発行したばかりの証明書は公開ログに載るまで数時間かかるので、見つからないときは時間をおいてやり直す
5. 結果：VPN らしいホスト名、SPF・DMARC の有無、メールとホームページの提供元の手がかり、カルテとの矛盾。カルテがあれば差分を見てから「カルテに反映する」。無ければ 5 問の初期値として保存され、次の段で「外部から推定」の印つきで出る

対象のホストには一切アクセスしない（ポートスキャン、Web の取得、ログイン画面の確認、TLS 接続を含む）。架空のドメイン `demo-seiko.example` を入れると、記録した応答を再生して試せる。公開 URL（後述）からは使えない。

## 2. 最初の5問に答える（`#/questions`）

業種、現場、仕事の置き場所（メール、ファイル、中核システム、ホームページ）、社外からのつなぎ方、バックアップ。文字入力はなく 2 分で終わる。「前の質問に戻る」で戻れる。外部確認を済ませていると、メール・ホームページ・つなぎ方に「外部から推定」の初期値が入る（初期値の選択肢を押すと外れるので、合っていればそのまま「次へ」）。答えるたびに構成図の枠が組み上がり、終わると担当者画面へ移る。この時点のカルテは枠だけで、会社名は「うちの会社」、対策の有無はすべて「未確認」。会社名は次のカルテの画面で登録する。

## 3. カルテの詳細を登録する（`#/profile`）

- **会社の情報**：会社名、従業員数、1 日の売上、送金額の目安、サイバー保険の通知期限、保守ベンダー。担当者のお名前は「自分で答える」の回答者として記録する（カルテには入れず、このブラウザだけに保存）
- **まず答えるとよい項目**：いまの事例の経路で問われている未確認を、入口に近い順に並べた一覧。押すとその行へ移る。ここから答える（またはベンダーに聞く）と結論が変わりやすく、他の未確認はこの攻撃の結論には関わらない。該当する資産と行は一覧でも先頭に寄せ、「この攻撃の経路：段階」の印が付く
- **確認項目**：構成要素ごとに対策（緩和策）が 1 行ずつ。「自分で答える」は 1 問の選択式で、選ぶとその場で保存して判定が更新される（根拠は「担当者登録」）。「ベンダーに聞く」は担当者画面の送信箱に確認依頼を作る。根拠は「外部確認 ＞ ベンダー回答 ＞ 担当者登録」の順に強く、外部確認の結果は担当者登録では変更できない。半年以上前の回答には「再確認を」の印が付く。VPN 装置とリモートデスクトップには製品名と版の欄がある（Claude には送らない）
- **業務の数値**：手作業で回せる日数、復旧日数、切り離したバックアップがあるときの復旧日数、影響先。止まる日数と取引先への影響の計算に使う
- **個人情報**：構成要素ごとの有無、件数、要配慮の有無。報告義務と期限の判定に使う
- **書き出し・読み込み**：カルテを JSON で保存し、別の PC で読み込める。カルテは自社の弱点の地図なので、取り扱いには注意する

未確認は決して「止まる」とは扱わない。未確認が残る間、結論は最悪の想定か「確認中」になる。

## 4. 記事を貼る（トップの手順 4）

- **URL**：公開された http(s) の記事。手元や社内のアドレスには向けない。ページが分かれている記事は続きも読む
- **本文**：40 文字以上を貼る
- **PDF**：20 MB まで。公的機関の事例集など。該当ページだけを書き出すと速い

Claude が読み、攻撃の段階ごとに戦術・手法 ID・記載か推定か・根拠文を返す。プログラムが手法 ID の存在、根拠文が原文にあること、型紙に合うことを確かめ、合わないものは捨てる。記事の中に指示らしき文があれば担当者画面に注意を出す（判定には使わない）。入口が記事に書かれていないときは型紙の入口候補（VPN 装置、リモートデスクトップ、メールなど）で判定し、その旨を注記する。

読んだ事例はこのブラウザに保存され、再読み込みしても残る（別の記事を読むか、記録済みの事例を選ぶと置き換わる）。

キーが無いサーバでは、読解のボタンを押すとその旨と「記録済みの事例から選ぶ」ボタンが出る。IPA 事例集 5 件の記録で判定まで進める。何も選んでいない間は既定で事例 1 を使っており、トップの手順 4 に「まだ選んでいません」と出る。

## 5. 結論を見る

### 担当者画面（`#/staff`）

- **結論**：止められます／抑えられます（切り離したバックアップで復旧できる）／大丈夫ではありませんでした／確認中／入口なし／対象外。未確認が残るときは上部に件数と、そのうち経路で問われている件数が出る。「大丈夫ではありません」が未確認の段階を「突破される」とみなした最悪の想定なら、その旨と段階名を明記する
- **型紙**：見出しに「型紙『…』で判定」。記事に入口が書かれていない事例（入口不明）は注記が出て、当てはまる型紙を全部展開するときは型紙の名前を並べ、根拠の経路ごとにも型紙を出す
- **経路図**：攻撃が構成図の上を進む。赤は突破、黄は未確認・人次第、緑は止まる・復旧できる。再生の速さと「動きを減らす」
- **時間軸**：業務の停止、復旧、取引先への影響、個人情報保護委員会への速報・確報・本人通知、保険、警察、資金の流出
- **対策ボタン**：対策を入れた状態で再判定する。効かない対策は理由つきでそう出る（例：認証を回避する脆弱性には多要素認証が効かない）。入れても止まらない段階は「適用中：この段階はまだ『未確認』」のように状態を添える。費用の目安は出典を確認できた単価だけ
- **ベンダーへの確認依頼**：未確認の項目に「ベンダーに確認する」（経路で問われている項目が先頭）。1 問だけの選択式の依頼文（キーがあれば Claude が書き、無ければテンプレート）が送信箱にでき、回答リンクをベンダーが開いて答えると判定がその場で更新される。依頼を作ると送信箱へ移る
- **業種を切り替えて、同じ攻撃を見る**：構成（VPN と保守接続、社内サーバ、クラウド同期のバックアップ、対策は未登録）を固定し、業種の構成パターンだけを製造業／事務所型／医療・福祉に替えたカルテで同じ事例を判定して並べる。止まる業務と日数、影響の違いを見る一場面で、自社のカルテは変えない
- **AI攻撃者**：抽象化したカルテ（役割と属性だけ）から別の入口を探し、プログラムが 4 点で検証したものだけを「AIが見つけた経路」として表示する。結論は変えず、警告として出す
- **知見なし比較**：知見ファイルを渡さない AI の対策一覧を、この経路に「効く／効かない／経路の外」に振り分ける
- **根拠**：各段階の手法 ID、緩和策 ID、根拠の種類、記事中の根拠文、矛盾、未確認の一覧

### 社長画面（`#/exec`）

専門用語と ID を出さずに、30〜40 秒の一本の物語として自動再生する。

### 社長向けの一枚（`#/onepager`）

結論、何が起きるか、止まる業務と日数、お金への影響、期限、必要な対策と費用と依頼先、出典と注記。

- **PDF をダウンロード**：印刷ダイアログを使わず、ブラウザの中だけで A4 縦（最大 2 ページ、節の途中では切らない）の `.pdf` を作って保存する。ファイル名は `社長向けの一枚_<会社名>_<YYYYMMDD>.pdf`。紙面は画像として貼るので文字は選択できない。会社の情報をサーバに送ることはない。作れなかったときは理由と「印刷ダイアログで開く」を出す
- **印刷する**：ブラウザの印刷で A4 縦の白地になる（印刷ダイアログの「PDF として保存」なら文字を選べる PDF になる）
- **共有リンクをコピー**：一枚の内容（結論から注記まで）と作成日時を圧縮して URL のフラグメントに載せる（`#/onepager?d=…`）。サーバには何も保存しないので、リンクを受け取った社長はカルテが無いスマホでも同じ一枚を開ける。URL は数 KB と長い。**内容が URL に入っているので、社外に送るときは中身を確かめる。** 会社カルテと経路図はリンクに含めない。開いた側では再計算せず、「{日時} 時点の判定（共有リンクで受け取った一枚）」と出所（作成した会社、事例、文の出所）を上部と注記に出す。クリップボードに書けないブラウザでは、リンクが画面の欄に出るので選択してコピーする
- 架空の会社の記録を指す短い形（`#/onepager?profile=demo-seiko&case=ipa-case-1&measures=vpn-update`）も残している。`rewrite=0` で Claude の言い換えを使わずテンプレート文にする

## 確認依頼のデモ（ベンダー役のスマホで回答する）

回答リンクは `PUBLIC_BASE_URL` を土台に作る。スマホで開くには手元のサーバを一時的に公開する。

```bash
# 1. 別のターミナルで手元の画面（5173）を公開し、表示される https://xxxx.trycloudflare.com を控える
cloudflared tunnel --url http://localhost:5173
```

```bash
# 2. 公開 URL を回答リンクの土台にして起動（.env に書いてもよい）
PUBLIC_BASE_URL=https://xxxx.trycloudflare.com pnpm dev
```

3. 担当者画面で未確認の項目の「ベンダーに確認する」を押す（架空の会社なら `http://localhost:5173/?profile=demo-seiko#/staff` で「管理者アカウント　M1026 特権アカウント管理」）
4. 送信箱の「メールソフトで開く」でベンダー役のスマホ宛てに送る（送信箱の回答リンクを直接スマホで開いてもよい）
5. スマホで回答リンクを開き、選択肢とお名前を入れて送る。担当者画面に「回答が届きました」と出て、判定が更新される（架空の会社では「全 PC で共通」で管理者権限の段階が黄から赤に変わる）

### 公開 URL の注意

- 公開 URL は一時的なもので、トンネルを止めれば無効になる。終わったら `cloudflared` を止める
- 公開 URL 経由（転送ヘッダつき）の要求は、既定では回答ページの API（`/api/requests/:token` と回答の送信）だけに制限する。外部確認の API も公開 URL からは使えない。他の API（会社カルテを扱うもの）を公開 URL から使うのは `UCHIDAI_ALLOW_REMOTE_API=1` を設定したときだけで、デモ以外では設定しない。CORS も手元の localhost と `PUBLIC_BASE_URL` だけに許す
- 依頼と回答は `apps/web/.data/requests.json`（git 管理外）に残る。送信箱の「送信箱を空にする」（または `curl -X DELETE http://localhost:5173/api/requests`）で消せる。サーバはメモリにも持つので、ファイルを消すだけでは再起動まで残る

## 困ったとき

- **「記事の読解には Claude API のキーが必要です」**：`.env` の `ANTHROPIC_API_KEY` を入れて `pnpm dev` をやり直す。入れない場合は記録済みの事例で進める
- **所有確認が通らない**：TXT の名前が `@`（ドメインそのもの）か、値が `uchidai-verify=` で始まっているか、DNS の反映を待ったかを確かめる。画面にいまの TXT レコードが出る
- **外部確認が 403**：所有確認が失効（24 時間）しているか、`node --watch` の再起動で消えている。「所有を確認する」を押し直す
- **共有リンクが開けない**：リンクが途中で切れていないか確かめる。画面に理由（文字が壊れている、形が違う、版が違う）が出る
- **カルテを消したい**：トップの「カルテを消す」。ブラウザの localStorage から消える（サーバには元から無い）。選んだ事例と担当者のお名前も同じ localStorage にある（`uchidai.case.v1`、`uchidai.staffName.v1`）
- **スマホで見たい**：上部バーのナビは狭い画面では二段に折り返す。担当者画面の表は横にスクロールする


> カルテを JSON から読み込んだときは、ドメインの所有確認の状態は引き継がれません（外部確認の結果は持ち込んだ時点のものとして表示します）。外部確認を使うときは、所有確認をやり直してください。
