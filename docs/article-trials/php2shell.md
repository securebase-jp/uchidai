## 経路ごとの結果

### (a) KEV の表示

**前**：`knowledge/kev/products.yaml` は 14 製品（VPN・ファイアウォール・NAS・Exchange）で、PHP は無かった。画面で公開ホームページの製品に「PHP 8.4.26」と入れて突き合わせると、「製品名『PHP 8.4.26』は対応表のどの製品にも当たりません」で未確認のまま、判定は黄色のままだった。KEV のカタログ自体は取り込めていて、10/26 の 2 件も入っているのに、カルテと結びつかない状態。

**KEV の更新の仕組み（確認）**：サーバーの `POST /api/kev/refresh` が CISA の JSON（`KEV_URL` に固定。リダイレクトは追わない）を取得して `.data/kev.json` に保存する。24 時間以内は取り直さず、失敗したらキャッシュで続ける。対象企業のホストには一切アクセスしない。**製品の対応表と版の範囲表は人が書く**（ベンダーの公表資料から URL と確認日つきで転記）。新しい CVE が KEV に入ると、その製品が表にあれば「KEV にあるが範囲は未確認」として出る。ただし版が既存の範囲に入らなければ「確認した範囲には該当しない」になり、`knownExploited = false` が書かれる（TRIAL-P-007）。

**後**：`php-core`（PHP 本体）を足した。別名は `php8`、`php7`、`php5`、`php本体`、`php-fpm`、`mod_php`、`php-cgi`。「php」だけにしない（phpMyAdmin や PHPMailer に当たってしまうため。試験で確認）。KEV からは `PHP Group / PHP` と、`PHP / PHP`・`PHP / FastCGI Process Manager` を拾い、PHPMailer・phpMyAdmin は拾わない。範囲は php.net と JPCERT/CC で確認した 8.2〜8.5 の 4 系統（8.2.35、8.3.36、8.4.27、8.5.12 未満）で、2 件とも認証前の悪用（`authBypass: true`）。実際の KEV（2026.11.04）で `php2shell-probe.ts` を実行した結果：

### (c) 型紙と一枚

- PHP の脆弱性悪用は、ATT&CK の **T1190（公開アプリケーションの悪用）**、**T1505.003（Web シェル）**。`knowledge/attack/enterprise.json` に存在することを確かめた。
- **型紙**：公開サーバーへの侵入・持ち出しは `data-breach-intrusion`（社内に置いた公開ホームページから、管理者権限、サーバー区画を経て持ち出す）が当たる。`data-breach-web`（ページを改ざんして入力情報を窃取）は、フォームの改ざんが書かれた記事向けで、バルテックの 2 件は当たらない。`ransomware` も入口に entry.web（T1190）を持つが、記事の種類が違う。`account-takeover-service` は会員向けサービスへの不正ログイン用で、脆弱性の悪用とは別。
- **判定ルール**：`web.entry.exploit`（T1190、T1505.003）が、KEV の `knownExploited = true` を最初に見て突破される、版が修正済みで更新管理があれば止められる。今回、理由の文に PHP を加えた。
- **一枚の初動**：公開ホームページの対策は「ホームページの CMS・追加機能を更新する」「管理画面に多要素認証」「改ざん検知」。**PHP の版を更新する、Web シェルの痕跡を確認する、という初動は無い**（TRIAL-P-004、P-006）。

## 方法の注意・限界

- **集めた範囲**：公開の検索で、PHP2Shell への対応・被害を会社自身が公表したものを探した。網羅ではない。被害を公表した国内の例を見つけられなかったのは、「無かった」ことの証明ではない（検索の限界、公表が遅れる可能性、IPA の把握は 10/27 時点）

- 追加した試験用の道具は、Claude の API を呼ぶのは `run-ir.ts` だけ。本文は `eval/.cache/trials/` に置き、リポジトリには入れていない
