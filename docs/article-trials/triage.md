## まとめた 5 つの塊（優先順）

### C1　出来事の確度（高 4・中 4）　最優先

一枚が「確認されています」と書く条件が、読解の `source: stated` だけで決まっている。前回の TRIAL-001 の修正で、`stated` を「確認されています」に固定した。そのため、読解が `stated` を誤って付けた記事（痕跡なし、おそれ、侵入方法の記載なし）が、そのまま「確認された事実」として社長に出るようになった。修正の副作用として表に出た問題。

- 課題：D-002、R-001、R-002、R-004（高）／R-007、S-003、B-007、B-011（中）／S-008、R-009、D-012（低、手法の付け方）
- 直し方：読解に確度の欄（確認／おそれ／痕跡なし／主張／記載なし）を持たせ、`stated` は「記事が出来事として書いている」ものだけにする。入口の記載がなければ手法を付けず `unknown` にそろえる。一枚は、「記事で確認された出来事」と「御社に当てはめた試算」を別の文にし、試算には「御社の場合は〜と見込まれます」と書かせる。検証で、確度に合わない言い方を弾く。
- 触る所：`packages/llm`（読解のスキーマ、指示文、`verifyCase`、`onepager-writer.ts`）、`packages/engine/src/onepager.ts`

### C2　入口の種類（高 2・中 4）

- 課題：TRIAL-004、D-003（高）、R-003（高）、S-002、R-006、D-004、TRIAL-008（RDP の対策ボタンが無い）
- 直し方：読解の入口の段階に入口の種類（vpn / rdp / network-device / vendor / credential / mail / web / none）を持たせる。一致する資産が無いときは、候補に切り替えず「カルテに、この入口になる資産が登録されていません」と出す（TRIAL-002 と同じ扱い）。RDP と Web の対策ボタンを足す（単価は出典があるものだけ）。
- 触る所：`packages/llm`（読解）、`packages/engine/src/evaluate.ts`（`entryFits`）、`types.ts`、`knowledge/measures.yaml`

## F1 の結果：出来事の確度（C1）の直しと再試験（11/5）

**何を直したか**（理由：一枚が「確認されています」と書く条件が、読解の `stated` だけで決まっていたため、読解が `stated` を誤って付けた段階が、そのまま事実として社長に出た）

- 読解に確度の欄 `certainty`（`confirmed` / `possible` / `exposed_only` / `no_trace` / `claimed` / `not_stated`）を持たせた。`stated` は「記事が出来事として書いているもの」だけ。指示文にも、「可能性・おそれ・とみられる・考えられる」は `inferred`＋`possible`、「痕跡は確認されず」は `no_trace`、攻撃者の主張は `claimed`、「閲覧できる状態だった」だけは `exposed_only`、「記載なし」は `unknown`＋`not_stated`（手法なし）と書いた。PM の案の 5 つ（確認／おそれ／痕跡なし／主張／記載なし）に、D-002 の案の `exposed_only`（閲覧できる状態だけで、取得は書かれていない）を足して 6 つにした。
- `verifyCase` が、記事の書き方の語から**確度をプログラムで補正**する（Claude が `stated` を付けても下げる）。入口の段階で、根拠文が入口の手段に触れていない手法は外す（B-007）。根拠文の照合にタイトルを足し、タイトルにしか無い根拠文は `stated` にしない（B-011）。戦術と手法の不一致を `warnings` に出す（S-008、R-009、D-012）。手法は、記事が手口を書いていなければ親手法・最大 2 つにとどめる指示。
- 補正の精度：「可能性がある〇〇（名詞）」や、複数の節がある根拠文の「可能性」は、別の出来事にかかることがあるため、その段階の確度を下げない（最初の実装で、ベル・データの入口と隔離が全部「可能性」になったのを直した）。
- 一枚の言い換え：確度を入力に渡し、確度ごとに言い方を固定した（可能性→「可能性があるとされています」、閲覧できる状態だけ→「実際に取得されたかは確認されていません」、痕跡なし→「痕跡は確認されていません」、主張→「主張しています」、公開済み→「すでに公開されています」）。止まる業務・日数・金額は別の文にして「御社の場合は〜と見込まれます」と書かせる。**試算の文、または業務停止に触れる文に「確認されています」を使うと検証で捨てる**。記事で確認された出来事が無いのに「確認されています」と書いた文、確度ごとの固定の言い回しが欠けた文も捨てる。段階名の「・業務停止」は入力から外した（言い換えが記事の事実の文に混ぜるため）。テンプレート文（`packages/engine/src/onepager.ts`）も同じ規則で、確度の印がある段階だけ別の文を足す（印が無い事例の文は変わらない）。
- 言い換えが応答の形に合わなかったときの注記を、「Claude を呼べなかった」から「応答が決められた形に合わなかった」に直した（R-007）。文の数の上限を 8 に広げた。
