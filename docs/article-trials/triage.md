## まとめた 5 つの塊（優先順）

### C1　出来事の確度（高 4・中 4）　最優先

一枚が「確認されています」と書く条件が、読解の `source: stated` だけで決まっている。前回の TRIAL-001 の修正で、`stated` を「確認されています」に固定した。そのため、読解が `stated` を誤って付けた記事（痕跡なし、おそれ、侵入方法の記載なし）が、そのまま「確認された事実」として社長に出るようになった。修正の副作用として表に出た問題。

- 課題：D-002、R-001、R-002、R-004（高）／R-007、S-003、B-007、B-011（中）／S-008、R-009、D-012（低、手法の付け方）
- 直し方：読解に確度の欄（確認／おそれ／痕跡なし／主張／記載なし）を持たせ、`stated` は「記事が出来事として書いている」ものだけにする。入口の記載がなければ手法を付けず `unknown` にそろえる。一枚は、「記事で確認された出来事」と「御社に当てはめた試算」を別の文にし、試算には「御社の場合は〜と見込まれます」と書かせる。検証で、確度に合わない言い方を弾く。
- 触る所：`packages/llm`（読解のスキーマ、指示文、`verifyCase`、`onepager-writer.ts`）、`packages/engine/src/onepager.ts`

### C2　入口の種類（高 2・中 4）

読解に入口の種類が無く、手法 ID だけで資産に対応づけるため、リモートデスクトップ、委託先の認証情報、保守接続が、カルテの VPN 装置に当たる。4 つの試験すべてで出た。

- 課題：TRIAL-004、D-003（高）、R-003（高）、S-002、R-006、D-004、TRIAL-008（RDP の対策ボタンが無い）
- 直し方：読解の入口の段階に入口の種類（vpn / rdp / network-device / vendor / credential / mail / web / none）を持たせる。一致する資産が無いときは、候補に切り替えず「カルテに、この入口になる資産が登録されていません」と出す（TRIAL-002 と同じ扱い）。RDP と Web の対策ボタンを足す（単価は出典があるものだけ）。
- 触る所：`packages/llm`（読解）、`packages/engine/src/evaluate.ts`（`entryFits`）、`types.ts`、`knowledge/measures.yaml`
- C1 と読解のスキーマを同時に触るため、C1 のあとに直す。

### C3　情報漏えいで「止まる業務・売上影響」が出る（高 1）

- 課題：D-001（高）
- **状態：修正済み（2026-11-05）**。`damage-types.yaml` に `stopsOperations` を足し（ransomware だけ true、data_breach・account_takeover・bec は false、省略時は true）、`computeImpact` が false の種類で止まる業務・復旧日数・売上影響・取引先への影響日を空にする。報告義務・期限・送金額は残る。計器（「業務停止 なし」）と再生の動き（業務の層に連鎖しない）も合わせた。
- 再試験（agc、montbell、nagasaki-manabie。同じ読解で前後を比較）：デモ精工「受注・生産管理と設計、10 日、約 1 億円」→ なし、5 問のカルテ「受注、在庫・発注、出荷・配送、7 日」→ なし。報告義務と期限は変わらず。ランサムウェアの事例 1 は変化なし。詳細は `breach.md` の「TRIAL-D-001 の修正と再試験」。
- 残り：取引先との契約上の通知（`partner-notice`）が、止まる業務の無い情報漏えいでは時間軸に出ない。5 問のカルテの一枚（テンプレート文）は「止まる業務なし」と明示しない（C1 の担当）。
- 触った所：`packages/engine/src/impact.ts`、`knowledge.ts`、`knowledge/damage-types.yaml`、`apps/web` の `Meters.tsx`、`playback.ts`。

### C4　第三者に起きた被害を、自社のものとして書く（中 5）

- 課題：S-001、S-004、S-005、S-007、R-006、D-004
- 直し方：`Case` に、被害を受けた側（自組織の同種／委託先・取引先）を持たせる。第三者のときは、一枚に「これは委託先で起きたことです。御社が同じ立場なら」と添える。型紙「取引先・委託先の停止」と、委託先管理の対策群を足す（出典は個人情報保護委員会、IPA の資料）。
- C2 の入口の種類（`vendor`）のあとに行う。

### C5　報告義務の安心側（中 4）

- 課題：D-006、D-007、B-004、D-011、B-002
- 直し方：対象外の一枚に「個人情報が見られた可能性があれば、報告が必要になることがあります」を足す。`blocked` の一枚から「報告も必要ありません」を外す。乗っ取りを含む経路では「メールの中身を見られた可能性。確認が必要」と出す。
- C1 の一枚の文の作りが固まってから行う（同じ文を触るため）。
