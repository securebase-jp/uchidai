### 動画に出す数字（出典あり）

- 警察庁 令和 7 年の統計：ランサムウェア被害にあった企業・団体等のアンケート（有効回答 92 件）で、感染経路は **VPN 機器が 61 件**。→ 「入口は、ほとんどが出入り口の機器」。出典は `knowledge/entry-candidates.yaml`。**ただし、警察庁サイト上の掲載場所が「要確認」のまま**（読んだ PDF は奈良県警の掲載分）。動画に出す前に確認が要る
- IPA 事例集 被害事例 1：従業員 80 名・兼務の情シス 2 名の製造業、想定被害額 4,600 万円（別紙の計算明細）。冒頭のチャットに貼られるリンクの事例そのもの
- 採点：知見あり 95%／知見なし 92%（正解データ 10 件）。差は 3 ポイントと小さいので、点数だけで押さない。実際の報道記事 12 本で、被害の型の一致は 12/12

## 2. ここまでの開発のふりかえり

- **核の体験**：報道の事例リンクを貼ると、Claude が攻撃を段階に分けて読み、同じ攻撃が自社の構成図の上をどう進むかを再生する。結論は「うちの会社は、大丈夫ではありませんでした」か「止められます」。対策を一つ入れると、結論が変わる。判定・計算・期限は、ルールと固定データからプログラムが決める
- **最初の絵コンテのあとに増えたもの**：自社ドメインの外部確認（DNS の TXT で所有確認、DNS と証明書の公開ログだけを参照、対象には触れない）／最初の 5 問で構成図が組み上がる／CISA KEV との突き合わせ／番号つきメールで確認し返事を入力する方式／業種切り替え／時間軸／費用の目安／社長向けの一枚（PDF）
- **開発の跡**：5.5 日で 321 コミット、採点の記録 79 回、約 40 の並行セッション。監査セッションで重大な穴（記事 URL の SSRF、公開 URL 経由の無認証 API、偽の所有確認など）を見つけて修正。開発者が正解データを 1 件ずつ確認。通しテストと全体テストで見つけた不具合を、その場で直した
- **旧脚本の弱点**：①誰のどの課題かを言葉で言い切っていない ②場面 4 が 167 字で専門語が多い ③体が反応する山がない ④外部確認・5 問・KEV・メール確認が映らない ⑤ Claude Code の使い方が 15 秒で、「Claude の活用」と「深さ」の基準に十分応えていない ⑥終わりが技術の列挙で、誰に届くかで終わらない
- **注意**：知見あり／なしの差は 3 ポイント。画面の文字が小さいので、動画では寄り（拡大）が要る

## 3. 脚本の方針

### 誰の、どの課題か

- **誰の**：従業員数十〜数百人の会社で、総務などと兼務する、ひとりきりの情シス担当者と、その人に聞く社長
- **どの課題**：他社の被害の報道を見た社長に「うちは大丈夫？」と聞かれても、大企業のように専門チームやコンサルに聞けず、「たぶん大丈夫」としか言えない
- **壁の外側にいるひとり**：この人を阻んでいる壁は 3 つ。①専門知識（記事が専門用語だらけ）②相談相手と予算（誰もいない）③時間（調べるのに何日もかかる）。場面 2 でこの 3 つが壁として出て、場面 3〜9 の操作で崩れていく
- **解決**：同じ攻撃が自社で起きたらどう進むかを再生して、止まるか・どの一手が効くかを、根拠つきで、数分で答える。専門家が経営層に返している「結論・根拠・次の一手」を、ひとりに

### 約束事

1. **専門語を使わない**。使うときは、たとえで言い換える（下の表）。手法 ID などは、画面に一瞬映すだけで読み上げない
2. **ナレーションは 1 場面 1 メッセージ**。画面で見えていることは、読み上げない
3. **山を 3 つ作る**：①結論（静けさから一気に）②「効かない」と弾かれる瞬間 ③社長の「じゃあ、それやろう」
4. **架空の会社・実際の記録を、画面に明記する**（デモ精工は架空。AI 攻撃者と一般的な AI の出力は、実際の出力の記録）
5. **BGM は使わない**（仕様）。効果音は、自作の合成音だけで足す（決定済み。下の「効果音」）

| 専門の言葉                 | 動画での言い方                                                       |
| -------------------------- | -------------------------------------------------------------------- |
| VPN 装置                   | 「出入り口の機器」（初出は「社外から会社につなぐ、出入り口の機器」） |
| 脆弱性・更新していない     | 「欠陥が残ったまま」「直していない」                                 |
| 管理者権限                 | 「会社の合鍵」                                                       |
| 多要素認証                 | 「ログインの鍵を二重にする」                                         |
| バックアップが暗号化される | 「予備のデータまで人質に」                                           |
| 保守ベンダーの遠隔接続     | 「取引先の保守業者が使う、遠隔の裏口」                               |
| AI 攻撃者                  | 「AI の攻撃者」（下見をするだけで、攻撃はしない）                    |

## 4. 脚本（案）

合計 3 分（180 秒）、11 場面、読み上げ約 740 字（空白と記号を除く。仕様の上限は 750 字前後）。「画面」は、いま実装されている画面のどれを使うか。

### 全体の起伏

```
0:00 ─ 問い（チャット：残す）─────────────── 0:30   誰の・どんな課題
0:30 ─ 見る（宣言 → 記事 → 自社の姿）─────── 1:02
1:02 ─ 起きること（再生・AI・確認・結論）──── 1:55   ← 山① 結論
1:55 ─ 変えられる（効かない／止まる）─────── 2:15   ← 山② 「効かない」
2:15 ─ 返す（社長の一枚）─────────────────── 2:28   ← 山③ 「じゃあ、それやろう」
2:28 ─ どう作ったか → 続けて使う → 締め ──── 3:00   Claude の活用・深さ・継続
```

### 場面ごとの脚本

**場面 1　社長の一言（0:00–0:15）　【残す＋帯を足す】**

- 画面：チャット。社長から IPA 事例集のリンクと「これ、うちは大丈夫？」が届く（旧場面 1 のまま）
- 読み上げ：「ある朝、社長からチャットが届きました。ニュースの事例のリンクと、ひとこと。『これ、うちは大丈夫？』」
- 演出（足す）：最初の 3 秒から、画面の下に細い帯。「従業員 120 人の部品メーカー（架空）　情シスは、ひとり。」。**誰がどんな場面かを、最初の数秒で言う**

**場面 2　答えられない担当者（0:15–0:30）　【残す＋一言足す】**

- 画面：担当者の入力欄。「たぶん大丈夫だと思いますが…」と打っては消し、「少し時間をください。調べます。」だけ送る（旧場面 2 のまま）
- 読み上げ：「ひとりで情シスを担当する彼は、答えに詰まります。対策はしているはず。でも、この攻撃がうちで止まるかは、誰にも言えません。」
- 演出（足す）：最後の 3 秒、チャットが暗く沈み、3 枚の壁が順に立つ。「専門知識」「相談相手と予算」「時間」。白い字「大企業には、専門チームがいる。この人には、いない。」（ナレーションは止める）

**場面 3　ウチダイ登場・リンクを貼る（0:30–0:48）　【宣言】**

- 画面：暗転 → タイトル「ウチダイ　＝　うちの会社は大丈夫か？」と 3 行の宣言（誰の：ひとり情シスの／どんな課題を：社長の「大丈夫？」に答えられない／どう解決：同じ攻撃が自社で起きたらどうなるかを再生し、根拠つきで答える）→ 小さく実際の数字（警察庁の数字。決めたいこと 1）→ 記事のリンクを貼る → 読解結果（「記載／推定／不明」のタグ。手法 ID は一瞬）
- 読み上げ：「ウチダイは、ひとり情シスのための道具です。同じ攻撃が自社で起きたらどうなるかを再生し、社長の『大丈夫？』に根拠つきで答えます。記事のリンクを貼ると、クロードが攻撃を段階に分けて読みます。」
- 演出：壁の 3 枚のうち「専門知識」の壁が、最初に崩れる（記事が、段階に分かれて読める形になる）

**場面 4　自社の姿（0:48–1:02）　【新規：demo-sec.com の実際の外部確認の記録から作る】**

- 画面：実在ドメイン demo-sec.com を、録画の前に実際に外部確認して得た結果の記録（DNS の応答と証明書の公開ログの行）を再生する（決定済み。下の「場面 4 の作り方」）。ドメインを入れる → 所有確認 → 結果が 3 つ、順に出る。①「VPN 用のホスト名が公開されている（vpn.demo-sec.com）」②「DMARC なし」③「廃止したはずの旧キャンペーンサイトの証明書が、まだ残っている」（カルテとの食い違い）。「対象のホストにはアクセスしません」を大きく。続けて最初の 5 問で、構成図のノードが順に現れる
- 読み上げ：「自社の姿は、公開記録だけで外から見ます。サーバには触れません。出入り口の機器、廃止したはずのサイト。外から見えるものが、構成図に組み上がります。」
- 演出：結果の 3 つは各 1.5 秒で、図が組み上がる動きを主役にする。「実際に外から見た記録（2026-11-0x、demo-sec.com）」の札を出す

**場面 5　攻撃の再生とベンダー確認（1:02–1:28）　【見せ場】**

- 画面：担当者画面の再生。赤い線が、出入り口の機器 → 管理者（黄）→ サーバ → バックアップ → 生産管理と進み、業務の層が落ちる。「経過 Day」「業務停止」「売上影響」が回る。続けて、黄色のノードから「ベンダーに確認する」→ 番号つきのメール文 → 返事の番号を入力 → 黄色が赤に変わる
- 読み上げ：「同じ攻撃を、自社の図の上で再生します。入口は、更新していない出入り口の機器。赤い線が、破られた場所です。会社の合鍵にあたる管理者の権限、サーバ、そして予備のバックアップまで。黄色は、まだ確認が取れていない所。保守業者に一問だけ聞いて返事を入れると、赤に変わりました。」
- 演出：速さ ×1.5。破られた場所ごとに図が寄る。黄 → 赤は、そこだけ寄って 0.5 秒。メールの入力の指は見せない
- 注意：旧絵コンテの「回答が自動で届く」は、いまの方式（返事を担当者が入力）に合わない。入力を操作として見せる

**場面 6　AI 攻撃者（1:28–1:40）　【Claude の新しい使い方】**

- 画面：AI 攻撃者のターミナル風のログ → 図に、点線の新しい入口（保守用リモート接続）が「AI が見つけた経路」として現れる。「実際の出力の記録」の札、「採用 3・破棄 0」「検証 ✓ ✓ ✓ ✓」
- 読み上げ：「さらに、エーアイの攻撃者に下見をさせます。報道になかった別の入口を見つけました。保守業者の、遠隔の裏口です。ルールで裏を取れたものだけを表示します。」
- 演出：ログは速く流し、検証の瞬間だけ止める。画面の下に「AI は下見するだけ。外部通信も実行の権限もありません」

**場面 7　結論（1:40–1:55）　【山①】**

- 画面：2 秒の無音と暗転のあと、「うちの会社は、大丈夫ではありませんでした」が明朝体で大きく出る → 4 つのタイル（止まる日数、取引先への影響、売上、報告義務）→ 時間軸（Day 0〜60）に取引先・警察・個人情報保護委員会の期限が並ぶ
- 読み上げ（無音のあと）：「結論です。うちの会社は、大丈夫ではありませんでした。業務は最長十日止まり、売上への影響は約一億円。個人情報の報告期限も、時間軸に並びます。」
- 演出：売上の数字を 0 から約 1 億円まで数え上げる。画面の隅に「この判定は、AI ではなく、ルールと会社カルテで決めています」「デモ精工（架空）」

**場面 8　一手で変わる（1:55–2:15）　【山②】**

- 画面：「対策を一つ入れて、もう一度」。①「VPN に多要素認証」→ 盾が出るが、赤い線が横を回り込み、「この経路には効きません」②「VPN 装置の更新」→ 線が入口の壁で止まり、緑に。時間軸の出来事が消え、結論が「止められます」に変わる ③ 一般的な AI の提案（8 件）と左右に並べ、「多要素認証」にだけ「効かない」の印
- 読み上げ：「では、どの一手が効くのか。ログインの鍵を二重にしても、この攻撃は鍵を通らないので止まりません。入口の機器を更新すれば、入口で止まります。一般的なエーアイは、効かない対策も勧めました。」
- 演出：①は、弾かれる瞬間に無音の間。②は、緑が広がる瞬間に結論の文字が反転。③は右の一件だけに印がつく。ここが「記事を貼ると AI が答えるだけのチャット」ではないことを示す
- 壁：「相談相手と予算」の壁が崩れる（どの一手が効くかを、専門家なしで）

**場面 9　社長への回答（2:15–2:28）　【山③】**

- 画面：社長向けの一枚（止まる業務、金額、期限、必要な対策と費用の目安）を、スクロール 2 回まで → チャットで送る → 社長「じゃあ、それやろう」
- 読み上げ：「社長には、専門用語のない一枚を送ります。止まる業務、金額、期限、必要な対策。返事は、ひとこと。『じゃあ、それやろう』」
- 演出：返事は一拍おいてから出す。冒頭と同じチャット画面に戻る。最後の壁「時間」が崩れ、「数分で、根拠つきで」の字

**場面 10　Claude をどう使い、どう作ったか（2:28–2:52）　【Claude の活用・深さ】**

- 画面：エンドカード前半（動く図）。左に「Claude の使い道」：読む（記事 → 段階、根拠文つき）／探す（AI 攻撃者）／書く（ベンダーへのメール、社長の一枚）／比べる（知見なしの AI）。その右に「検証」：手法 ID の照合、根拠文、判定ルール、数値の検証、通らなければ捨てる。右に「判定と計算は、プログラム」。次に Claude Code の跡：約 40 の並行セッション（領域ごとの worktree）。役割分担を 2 行で出す：**Fable（計画・統合・レビュー）／Sonnet（実装）**。続けて採点の推移 → 監査セッションが見つけた穴の件数 → 321 コミット
- 読み上げ：「クロードが担うのは、読む、探す、書く。答えはルールで検証し、通らなければ捨て、判定と計算はプログラム。開発は、計画と統合をフェイブル、実装をソネットが担い、約四十の並行セッションを、採点と監査で回しました。」
- 演出：1 枚の図で、2 段に動かす（前半 12 秒：Claude とプログラムの役割、後半 12 秒：Claude Code の跡）。数字は読み上げず、画面で数え上げる
- 決定済み：モデルは名前（Fable、Sonnet）で出す。Mythos の名は出さない。製品の中で動くモデルは「Sonnet 5.5」と書く

### 場面 4 の作り方（記録から再生する）
