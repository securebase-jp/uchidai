# Claude Code での進め方の記録

ハッカソン期間中に、Claude Code をどう使って進めたかの記録。デモ動画の最後で紹介する。

## 11/2（月）

- 12:45 仕様書を読み込み、開発計画（`docs/development-plan.md`）を作成。確認事項 18 件を開発者に提示
- 14:10 開発者の回答：ローカルで動くデモを優先（ドメインは別途）、リポジトリ作成 OK、API キー配置済み、根拠文は短い抜粋を出典つきで保持
- 14:20 最初のコミット：評価の仕組みの骨組み（採点器、正解データのスキーマ、記録再生）。仮の記録での初回採点は総合 57%（段階 40%、区別 100%、手法 30%）
- 14:25 GitHub `securebase-jp/uchidai` を公開で作成。シークレットスキャンとプッシュ保護を有効化。マイルストーン 8 件、Issue 51 件を投入
- 14:40 ATT&CK Enterprise v20.0（2026-10-13）を取り込み。v20 で T1656 なりすまし が T1684.001 に置き換えられ、防御回避が「潜伏（Stealth）」に改名、「防御の無力化（TA0112）」が新設されていた。廃止 ID の置き換え表を取り込みに含め、Claude が古い ID を返しても照合できるようにした
- 14:50 KEV 該当の VPN 製品は FortiOS（CVE-2024-55591、認証回避型）に決定。共通の型、役割の枠、日本語ラベル、デモ用カルテ、知識ファイルの検証コマンドを追加
- 15:00 S1（読解）と S2（判定エンジン）を worktree で起動したが、Claude Desktop のリポジトリ信頼待ちで動かず。S2 の内容（構成グラフ、型紙、判定ルール表の DSL、経路探索、対策の適用、AI 経路の検証、知見なし比較の振り分け）を主セッションで実装。デモ用カルテで仕様の想定結果（事例1 赤→多要素認証は効かない→更新で止まる→切り離しバックアップで抑えられる、事例5 人次第→社長の多要素認証で止まる、事例2 止まる、保守ベンダー接続の AI 経路、クラウドだけの会社は入口なし）を 18 件のテストで固定
- 16:50 S1（読解）と S2（エンジン監査）が完了。S1 は `packages/llm`（取り込み・読解・検証）と `pnpm eval --live` / `--no-knowledge` を実装し、5 事例 × 2 モードの実測を記録。S2 は main のエンジンを監査して不具合 8 件を修正、テスト 18→52 件、警察庁統計の件数を入口候補に記入。両ブランチを main にマージ（d859c87、3be2154）
- 統合後の評価：知見あり 90% / 知見なし 95%。知見ありが低いのは、事例 3・4（検証用）で型紙にない手法を設計どおり破棄するため（手法点 50%）。デモの 3 事例は判定を含め 97〜100%。最終判定は事例 1 breached、2 blocked、5 breached で正解と一致
- セッションの分け方（予定）：S0 基盤・統合（このセッション）、S1 記事の読解、S2 判定エンジン、S3 描画と動き、S4 経営の層、S5 外部確認、S6 AI攻撃者・比較、S7 連携・依頼、S8 デモモード・動画。各領域の完了時に監査セッション
