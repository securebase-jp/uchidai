# ポータブル ZIP で使いはじめる

Node も pnpm も Docker も入っていない PC で、ZIP を展開して「ウチダイを起動」をダブルクリックするだけで使えます。社内の PC に何かをインストールする必要はありません（管理者の権限も要りません）。ウチダイは手元の PC の中だけで動き、ブラウザで画面を開いて使います。

この ZIP には、ウチダイのプログラムと、動かすための Node.js（公式の配布物）が入っています。ZIP の大きさは約 70MB です。

## 対応している環境

| 環境                           | ダウンロードする ZIP           |
| ------------------------------ | ------------------------------ |
| Windows 10 / 11（64 ビット）   | `uchidai-<版>-win-x64.zip`     |
| Mac（Apple シリコン：M1 以降） | `uchidai-<版>-macos-arm64.zip` |
| Mac（Intel）                   | `uchidai-<版>-macos-x64.zip`   |
| Linux（x64、glibc 2.28 以上）  | `uchidai-<版>-linux-x64.zip`   |

Mac がどちらか分からないときは、画面左上のアップルメニューから「このMacについて」を開きます。「チップ」に Apple と出ていれば Apple シリコン、「プロセッサ」に Intel と出ていれば Intel です。Alpine などの musl 系の Linux は対象外です。

## 手順

1. **ダウンロードする**：ウチダイの GitHub の「Releases」ページから、自分の環境の ZIP をダウンロードします。同じ場所にある `SHA256SUMS` も一緒に取っておくと、次の手順で確かめられます。
2. **確かめる（おすすめ）**：ダウンロードした ZIP が、公開されたものと同じであることを確かめます。やり方は下の「[ダウンロードしたものを確かめる](#ダウンロードしたものを確かめる)」にあります。
3. **展開する**：ZIP を「すべて展開」します（下の注意をお読みください）。
4. **起動する**：展開したフォルダの中の、次のファイルを開きます。
   - Windows：`ウチダイを起動.bat` をダブルクリックします。
   - Mac：`ウチダイを起動.command` を、右クリック（または control を押しながらクリック）して「開く」を選びます。2 回目からは、ダブルクリックで開けます。
   - Linux：ターミナルで、展開したフォルダに移って `./start.sh` を実行します。
5. **ブラウザで開く**：画面（黒または白のウィンドウ）に「ウチダイの準備ができました。」と出ると、ブラウザで `http://127.0.0.1:8787/` が自動で開きます。開かないときは、ウィンドウに表示されたアドレスを、ブラウザのアドレス欄に貼ってください。
6. **終了する**：起動したときのウィンドウを閉じます（Ctrl+C でも止まります）。ウィンドウを閉じると、ウチダイは完全に止まります。また使うときは、もう一度手順 4 を行います。

展開するときの注意です。

- Windows では、ZIP を右クリックして「すべて展開」を選びます。ZIP の中を開いたまま、その中から直接ダブルクリックしても動きません。
- 展開先のフォルダの名前や置き場所は自由です。ただし、とても深い場所（フォルダの入れ子が深い場所）に置くと、Windows がファイルを展開できないことがあります。`C:\uchidai` や `デスクトップ` のような、浅い場所をおすすめします。
- 展開したフォルダを移動するときは、ウチダイを終了してから、フォルダごと移動してください。

## ダウンロードしたものを確かめる

`SHA256SUMS` には、各 ZIP の「指紋」（SHA-256 の値）が書かれています。ダウンロードした ZIP の指紋を計算して、同じ値になれば、公開されたものと同じ ZIP です。

Windows（PowerShell。ZIP のあるフォルダで開きます）：

```powershell
Get-FileHash .\uchidai-<版>-win-x64.zip -Algorithm SHA256
```

Mac：

```bash
shasum -a 256 uchidai-<版>-macos-arm64.zip
```

Linux：

```bash
sha256sum uchidai-<版>-linux-x64.zip
```

表示された値が、`SHA256SUMS` の同じ名前の行の値と、一文字も違わなければ大丈夫です（大文字と小文字は区別しません）。違うときは、ダウンロードが壊れたか、別のものに差し替えられた可能性があるので、使わずに取り直してください。

## 警告が出たとき

ウチダイの ZIP と起動のファイルには、Microsoft や Apple の「署名」がありません。署名には、証明書の購入や Apple の開発者登録（どちらも年ごとの費用）が要ります。ウチダイは個人が公開している OSS で、いまはその費用と手続きをかけていません。そのため、Windows と Mac は「発行元を確認できないファイル」として警告を出します。

警告が出ること自体は、ウイルスが見つかったという意味ではありません。ただし、署名が無いので、警告が出ても出なくても、そのファイルが安全だという保証にもなりません。だから、上の「確かめる」の手順（`SHA256SUMS` との照合）をおすすめしています。また、起動のファイル（`.bat`、`.command`、`start.sh`）は短い文字のファイルで、メモ帳などで中身を読めます。同梱している Node.js は、nodejs.org の公式の配布物で、公式の `SHASUMS256.txt` と照らして確かめたものです（ライセンス文は `runtime/LICENSE-Node.js.txt`）。

### Windows の「WindowsによってPCが保護されました」（SmartScreen）

1. 画面に出た青い警告の「**詳細情報**」を押します。
2. 出てきた「**実行**」を押します。

先に、ダウンロードした ZIP を右クリックして「プロパティ」を開き、下にある「ブロックの解除（許可する）」にチェックを入れて「OK」を押してから展開すると、警告が出ないことがあります。

ウイルス対策ソフトが `node.exe` や起動のファイルを止めたときは、その製品の画面で、展開したフォルダを例外に加えてください。会社の PC で、管理者が実行を禁止している場合は、情報システムの担当者に相談してください。

### Mac の「開発元を検証できないため開けません」（Gatekeeper）

1. `ウチダイを起動.command` を、右クリック（または control を押しながらクリック）して「**開く**」を選びます。
2. 警告の画面でも「**開く**」を押します。

これで 1 回許可すると、2 回目からは、ダブルクリックで開けます。ダブルクリックだと、警告に「開く」ボタンが出ないことがあるので、最初は必ず右クリックから開いてください。macOS の版によっては、「システム設定」→「プライバシーとセキュリティ」の下のほうに「このまま開く」が出るので、それを押す形になります（表示は版によって違います）。

それでも開けないときは、展開したフォルダの「ダウンロードしたものという印」を外す方法があります。ターミナルで、次を実行します（`フォルダの場所` は、展開したフォルダをターミナルにドラッグすると入ります）。

```bash
xattr -dr com.apple.quarantine フォルダの場所
```

これは、このフォルダの中身を信頼すると決めたときだけ行ってください。

## API キーの設定（任意）

Anthropic の API キーがなくても、判定、経路の再生、対策ボタン、記録済みの IPA 事例、最初の 5 問、確認依頼などは使えます。**記事の URL や本文を貼って読ませる機能と、文章の言い換えだけ**に API キーが要ります。

1. 展開したフォルダの `uchidai.env.example` をコピーして、名前を `uchidai.env` にします。
2. `uchidai.env` をテキストエディタで開き、`ANTHROPIC_API_KEY=` の行の先頭の「# 」を消して、`=` のあとに、自分のキーを書きます。
3. 保存して、ウチダイを起動し直します。起動のウィンドウに「設定ファイル uchidai.env を読み込みました。」と出れば、読めています。

Windows で、拡張子（`.example`）が見えないときは、エクスプローラーの「表示」→「表示」→「ファイル名拡張子」にチェックを入れてください。メモ帳で保存するときは、「ファイルの種類」を「すべてのファイル」にして、`uchidai.env.txt` にならないようにします。

注意です。

- キーは、使った分だけお金がかかる鍵です。`uchidai.env` は、他の人に渡さず、メールやチャットにも貼らないでください。ZIP を他の人に渡すときは、`uchidai.env` を抜いてください。
- キーはウチダイのサーバ（手元の PC の中のプログラム）だけが使い、ブラウザには渡しません。
- 同じ `uchidai.env` に、ポート番号（`API_PORT`）、プロキシ（`HTTPS_PROXY`）、メール送信（`SMTP_URL`、`MAIL_FROM`）なども書けます。見本の中に説明があります。
- パソコンの環境変数に `ANTHROPIC_API_KEY` を設定している場合は、そちらが優先されます。

## データの置き場所と消し方

| データ                                                                        | 置き場所                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 会社カルテ、選んだ事例、画面の設定                                            | **ブラウザの中**（localStorage）。ZIP のフォルダには入りません                                                                                                                                                |
| 確認依頼と回答、所有確認のトークン、CISA KEV の写し、外部確認の応答の一時保存 | あなたのユーザー領域の `uchidai` フォルダ：Windows は `%APPDATA%\uchidai`（`C:\Users\（あなた）\AppData\Roaming\uchidai`）、Mac は `~/Library/Application Support/uchidai`、Linux は `~/.local/share/uchidai` |

保存先は、起動のウィンドウにも「保存先」として表示されます。展開したフォルダの外にあるので、ZIP のフォルダを消したり、新しい版に差し替えたりしても、データは残ります。`uchidai.env` に `UCHIDAI_DATA_DIR=（フォルダの場所）` と書くと、保存先を変えられます。

消したいときは、次のようにします。

- **サーバ側のデータ**：ウチダイを終了してから、上の `uchidai` フォルダを削除します。
- **会社カルテ**：ウチダイの画面の「リセットする」で消せます。または、ブラウザの設定で、`127.0.0.1` のサイトのデータを削除します。会社カルテは自社の弱点の地図にあたるので、書き出した JSON の扱いにも注意してください。
- **すべて**：上の 2 つを行い、展開したフォルダも削除します。ウチダイは、PC にほかのものをインストールしていません。

## 更新する

1. 新しい版の ZIP を、古いものとは別の場所に展開します。
2. 古いウチダイを終了します（ウィンドウを閉じます）。
3. 古いフォルダの `uchidai.env`（作っていれば）を、新しいフォルダにコピーします。
4. 新しいフォルダから、ウチダイを起動します。
5. 動くことを確かめたら、古いフォルダを削除します。

データ（確認依頼など）は展開したフォルダの外にあるので、そのまま引き継がれます。会社カルテはブラウザの中にあるので、同じブラウザで同じアドレス（`http://127.0.0.1:8787/`）を開けば、そのまま見えます。

## ポートが使用中のとき

ウチダイは、通常 8787 番のポートを使います。すでにほかのアプリが使っているときは、8788、8789、…と、空いている次の番号に自動で移り、ウィンドウに「ポート 8787 は別のアプリが使っているため、8788 で起動します。」と出ます。ウチダイが二重に起動しているだけのときは、「すでに起動しています。そのまま画面を開きます。」と出て、いまの画面を開きます。

**ポートの番号が変わると、ブラウザの保存場所が変わります。** 会社カルテはブラウザの中にあり、アドレス（番号を含みます）ごとに別々に保存されるからです。8787 で使っていた会社カルテが、8788 では「空」に見えます。そのときは、次のどちらかにしてください。

- 8787 を使っているアプリ（古いウチダイが残っていないか）を終了して、ウチダイを起動し直す。
- 番号が変わる前に、会社カルテを「書き出し」て保存しておき、新しい画面で「読み込み」む。

使う番号を決めたいときは、`uchidai.env` に `API_PORT=8800` のように書きます（その番号が使用中なら、次の空き番号に移ります）。

## プロキシ環境（会社のネットワーク）

外のサイトへの通信を、会社のプロキシ経由にしているときは、`uchidai.env` に次の行を書きます（またはパソコンの環境変数 `HTTPS_PROXY` に設定します）。

```
HTTPS_PROXY=http://proxy.example.co.jp:8080
```

Claude の API、証明書の公開ログ（crt.sh など）、CISA の KEV の取得が、このプロキシを通ります。DNS の問い合わせは HTTP のプロキシを通らないので、社内で外への DNS が制限されていると、外部確認が使えないことがあります（その場合も、ほかの機能は使えます）。ユーザー名とパスワードが要るプロキシは `http://ユーザー名:パスワード@proxy.example.co.jp:8080` の形ですが、パスワードを書いたファイルの扱いに注意してください。

## 手元以外には公開しないでください

ウチダイには、ログインや認証がありません。そのため、ZIP 版は **手元の PC（127.0.0.1）だけ**で待ち受けるように固定してあり、`API_HOST` を設定しても無視します。ほかの PC からは開けません。

- 同じネットワークの人や、インターネットに向けて公開する使い方はしないでください（リバースプロキシやトンネルでの公開を含みます）。会社カルテには、自社の弱点の情報が入ります。
- 他の人に見せたいときは、画面の「社長向けの一枚」を、印刷または共有リンクで渡してください。共有リンクの中身はアドレスの中で完結し、ウチダイのサーバには届きません。
- 複数の人で使うときは、それぞれの PC に、それぞれ ZIP を展開してください。

## 起動しないとき

- 起動のウィンドウに出ている、最後の数行を確かめてください。「必要なファイルが見つかりません」と出たら、ZIP を展開し直します（展開が途中で止まっていることがあります）。
- ZIP の中から直接起動していないか、確かめてください（先に「すべて展開」します）。
- ウイルス対策ソフトが、展開したフォルダのファイルを隔離していないか、確かめてください。
- ポートの案内が出ているときは、上の「ポートが使用中のとき」を読んでください。
- Linux で「実行できない」と出るときは、展開したフォルダで `chmod +x start.sh runtime/node` を実行します（ZIP を展開するツールによっては、実行の権限が外れます）。

## 参考：ZIP の中身と作り方

展開したフォルダの中身は次のとおりです。

| 場所                                            | 内容                                                                                 |
| ----------------------------------------------- | ------------------------------------------------------------------------------------ |
| `ウチダイを起動.bat` / `.command` / `start.sh`  | 起動のファイル（環境ごとに 1 つ）                                                    |
| `はじめにお読みください.txt`、`導入の手引き.md` | この文書の要約と、この文書                                                           |
| `uchidai.env.example`                           | 設定の見本（値は入っていません）                                                     |
| `runtime/`                                      | 同梱の Node.js（`node`、`node.exe`）、起動処理、Node.js のライセンス文               |
| `app/`                                          | ウチダイのプログラム（画面、サーバ、判定の部品）、知識ファイル、記録、実行に要る依存 |
| `LICENSE`、`NOTICE`                             | ウチダイのライセンスと、外部データ（MITRE ATT&CK、IPA、CISA KEV など）の出典         |

ZIP は、リポジトリで次のコマンドを実行すると作れます（Linux か Mac で、Node 22.18 以上、pnpm、`unzip`、`tar` が要ります。4 環境ぶんの ZIP が、どの環境でも作れます）。

```bash
pnpm install
pnpm build
pnpm portable:build --target all --version 0.1.0
```

リリースは、`v` から始まるタグを push すると、GitHub Actions（`.github/workflows/release-zip.yml`）が 4 環境の ZIP と `SHA256SUMS` を作り、Windows・Mac・Linux で展開して起動する確認を通したあと、**下書き（ドラフト）の Release** に添付します。内容を確かめて、人が公開します。同梱する Node.js は、`scripts/portable/node-release.json` に版と SHA-256 を固定し、公式の `SHASUMS256.txt` と、この固定した値の両方に合わないときは、ZIP を作りません。
