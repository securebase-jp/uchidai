# 評価の仕組み

専門家（開発者）が作った正解データに対する、読解と判定の一致度を測る。改善はすべてこの点数で判断する。

## 構成

- `cases/*.yaml`：正解データ。IPA 事例集へのリンク、開発者自身の言葉での要約、正解の戦術・手法ID、記載／推定の区別、デモ用架空企業での結論。**本文は含めない**
- `recordings/*.json`：記録した Claude の応答。API キーがなくても採点できる。リクエストヘッダは保存しない。根拠文として IPA 事例集からの短い抜粋（1〜2文）を含むが、出典を明記した抜粋として扱い、本文全体は置かない（2026-11-02 に開発者と確認）
- `.cache/<caseId>.txt`：記事の原文（任意、git 管理外）。あれば根拠文が原文に実在するかを照合する
- `results/<日時>.json`、`RESULTS.md`：結果の記録

## 観点

| 観点               | 計算                                                                                   |
| ------------------ | -------------------------------------------------------------------------------------- |
| 段階の抽出         | 正解の段階のうち、同じ戦術の段階を出力できた割合                                       |
| 記載か推定かの区別 | 一致した段階のうち、記載／推定が合っていた割合                                         |
| 手法ID             | 完全一致 1.0、親手法のみ一致 0.75、戦術のみ一致 0.5 の平均                             |
| 根拠文             | 記載とした段階の根拠文が原文に実在し、正解の手がかりを含む割合（原文がなければ対象外） |
| 最終判定           | デモ用架空企業に当てはめた結論の一致（判定が未記録なら対象外）                         |

## 実行

```bash
pnpm eval                 # 記録データで採点し、結果を記録する
EVAL_NOTE="読解プロンプト v2" pnpm eval   # RESULTS.md のメモ欄に残す
```

Claude を呼んで記録を更新するコマンド（`--live`）と、知見ファイルなしで読ませる比較（`--no-knowledge`）は、読解（packages/llm）の実装と同時に足す。
